TECHNICAL REFERENCE / EGO CLI V0.1.0

Architecture of Ego CLI

Ego is a local decision-support and investigation tool. It coordinates authenticated AI CLIs, preserves disagreement, enforces read-only execution, and records model outcomes separately from human decisions. Its authenticated local service lets external applications inspect that environment without owning Ego's process.

02 / EXTERNAL APPLICATION SERVICE

A supervised, authenticated boundary

Ego owns the service process and its LaunchAgent. External applications remain narrow TCP clients: they validate the server, submit an explicit typed method, and render committed workflow, history, Decision, safety, and participant state.

→

→
SANDBOXED CLIENT External application Keychain credential · typed decoder
01

Install or update

ego service install

Captures the current executable and data directory, replaces the plist atomically, restarts the job, and validates the server proof.

02

Inspect health

ego service status

Separates installation, launchd, transport, protocol, stale-path, and HMAC proof states without parsing launchctl output.

03

Remove lifecycle only

ego service uninstall

Stops the known job and removes only Ego's plist. Credentials, configuration, SQLite, logs, and the executable remain.

FIXED LAUNCH CONTRACT

Ego owns the executable path

ProgramArguments = [
  "/absolute/path/to/ego",
  "service",
  "run"
]

No shell, configurable argv, XPC, SMAppService, application helper, or Roma Desk process launch is involved.

BIDIRECTIONAL AUTHENTICATION

Mutual proof, no token on the wire

server = HMAC(token, "server:" + nonce)
client = HMAC(
  token,
  "client:" + nonce + request metadata
)

The client verifies Ego before sending a typed request; Ego then verifies the client. Constant-time comparisons protect both proofs.

STRICT METHOD ALLOWLIST

Typed workflows, never generic execution

diagnostic · schema run.start · run.cancel runs.list · runs.get · runs.events decision.transition · decision.resolve

One explicit Decision or Investigation may run at a time. No command, argv, shell, provider, arbitrary context, raw output, or SQLite method exists.

LAUNCHAGENT

com.rrmarto.ego.service KeepAlive · Background · throttle 10s · umask 077

PRIVATE LOGS

service.stdout.log Separate stderr · no token · preserved on uninstall

INSTALLATION CHOICE

Global preferred Editable .venv supported; reinstall after moving or rebuilding it

03 / WORKFLOW RUNTIME

One runtime, two explicit agents

Decision and Investigation use different stage contracts and result semantics while sharing participant discovery, Seatbelt enforcement, events, persistence, and failure handling.

  1. 00
    Explicit request

    The interface selects Decision or Investigation; automatic routing remains deferred.

  2. 01
    Run creation

    Ego resolves the workspace, records initial Git state, and persists the run.

  3. 02
    Fail-closed probes

    Binary, version, required controls, authentication, and Seatbelt are checked.

  4. 03
    Stage barriers

    Available participants run in parallel inside each workflow stage.

  5. 04
    Final validation

    Citations and Git state are rechecked before the immutable result is stored.

  6. 05
    Human boundary

    Only a person can resolve a contested decision; investigation never creates that action.

05 / OUTCOME LOGIC

Models recommend; people decide

Structured validity is necessary but not sufficient. Ego limits confidence, degrades incomplete work explicitly, and stores human resolution without rewriting model output.

06 / SAFETY BOUNDARY

Read-only is verified, not assumed

Every runnable participant must pass a functional macOS Seatbelt probe. Ego confirms that reads work and writes fail before any provider can inspect the real workspace.

DOCUMENTED ADAPTER VARIANTS

Codex and OpenCode use Ego's external boundary

Codex cannot nest its internal Seatbelt inside Ego's wrapper. OpenCode does not expose a security sandbox. Both adapters declare the external-only requirement, run in isolated temporary state, and are refused if the verified wrapper is absent.

  • Private, temporary provider-specific authentication copies.
  • No inherited plugins, MCP servers, agents, commands, or cross-provider credentials.
  • Tools are enabled only for stages whose contracts permit local evidence access.
  • No user-selectable unsafe override exists in v1.

07 / EVIDENCE CONTRACT

Integrity is not semantic proof

Ego verifies that a cited path, line range, and hashes match the inspected workspace. It cannot prove that a participant interpreted that source correctly.

01

Path boundary

The normalized path must stay inside the selected workspace.

02

Exact lines

The requested range must exist and is extracted exactly.

03

Two hashes

The record stores both file and cited-fragment SHA-256 hashes.

04

Final revalidation

Citations and Git state are checked again before finalization.

EGO CAN VERIFY

  • Path
  • Line range
  • File hash
  • Fragment hash
≠

EGO DOES NOT PROVE

  • Semantic interpretation
  • Total absence of risk
  • Truth by consensus
  • Future correctness
